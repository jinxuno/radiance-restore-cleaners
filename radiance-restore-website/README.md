# Radiance Restore Cleaners — website

Static marketing site for Radiance Restore Cleaners (Radiance Restore LLC), a house cleaning
company serving Palm Beach County, Broward County and the Treasure Coast in Florida.

- **Live:** https://www.radiancerestore.org
- **Host:** Netlify, auto-deploying from `main`
- **Publish directory:** `radiance-restore-website/`
- **Stack:** hand-built static HTML. No framework, no build step at deploy time, no runtime JS
  dependencies. Every page ships as complete HTML with its CSS inlined in a `<style>` block.

---

## Quick start

```bash
git clone https://github.com/jinxuno/radiance-restore-cleaners.git
cd radiance-restore-cleaners/radiance-restore-website

# serve locally — any static server works
npx http-server . -p 8080
# or
python3 -m http.server 8080
```

Open http://localhost:8080. That's it — what you see locally is byte-for-byte what deploys.

### Deploying

Push to `main`. Netlify builds in under 15 seconds (there is no build command; it copies the
publish directory) and goes live. To roll back, use **Deploys → an older deploy → Publish deploy**
in the Netlify dashboard.

## URL conventions

Netlify **Pretty URLs** is on, so `/foo.html` is served at `/foo` and links in served HTML have
`.html` stripped automatically.

| Page type | URL shape | Example |
|---|---|---|
| Core service | `/<service>.html` | `/standard-cleaning.html` |
| Original city page | `/<city>-house-cleaning.html` | `/palm-beach-house-cleaning.html` |
| Local landing page | `/<service>-<city>` | `/house-cleaning-boca-raton` |
| Guide article | `/<keyword-phrase>` | `/how-baseboard-cleaning-works-in-port-st-lucie` |
| Service-area hub | `/service-areas` | |

### `_redirects`

Every rule uses Netlify's forced form (`301!`) so the redirect fires even when a file still exists
at the old path. Three groups:

1. **Guide articles** — the 60 old `<topic>-cleaning.html` filenames → their new keyword slugs.
   The old files are still in the repo; the forced redirects mean they are never served.
2. **Local landing pages** — `/<slug>.html` → `/<slug>` (extensionless canonical).
3. **Canonical host** — `radiancerestore.org/*` → `www.radiancerestore.org/*`.

If you rename a page, add a `301!` rule. Do not delete old rules — inbound links depend on them.

## Local pages and keyword clustering

The 31 local landing pages exist to rank for city+service queries. They were built from a
241-keyword list that reduced to **31 clusters**, each owning **exactly one primary keyword**.
That constraint is the whole point: two pages competing for the same primary keyword split their
own authority (keyword cannibalisation) and neither ranks.

- `keyword-clusters.json` — every page mapped to its primary keyword and 4–5 secondaries.
- `keywords-excluded.json` — the 29 keywords deliberately dropped, with reasons: competitor
  brand names, job-seeker intent, and malformed scraper artifacts.

**Before adding a page, check `keyword-clusters.json`.** If the keyword you're targeting is
already a primary or secondary somewhere, extend that page instead of creating a new one.

## On-page SEO contract

Every page satisfies the same checklist. If you edit or add a page, keep all of it true:

**Head** — title 50–60 chars with the primary keyword near the start; meta description 150–160
chars; canonical URL; Open Graph (`og:image` = `/og-card.jpg`, 1200×630); Twitter
`summary_large_image`; `lang`, viewport, charset, favicon.

**Structure** — exactly one `<h1>` containing the primary keyword; `h2 → h3` with no skipped
levels; `<main id="main">` landmark; a skip-to-content link; breadcrumbs.

**Body** — primary keyword inside the first 100 words; the query answered directly in the first
paragraph (`.answer-box`); short paragraphs; active voice. Local pages carry a table of contents
with jump links and back-to-top links.

**Schema (JSON-LD)** — `Service` + `FAQPage` + `BreadcrumbList` on local pages;
`HouseCleaningService` (with `openingHoursSpecification`, `knowsAbout` for the 60 GBP service
categories, and `sameAs` pointing at the Google Business Profile) on core pages;
`BlogPosting` + `FAQPage` + `BreadcrumbList` on guides.

**Links** — 3–5 internal links with descriptive anchor text, never "click here"; 2–3 external
links to authoritative `.gov`/`.edu` sources, `target="_blank" rel="noopener"`. **Every external
URL was fetched and verified before being cited.** If you add one, verify it loads.

**Images** — descriptive filenames, real alt text, explicit `width`/`height` (prevents layout
shift), `loading="lazy"` below the fold. The LCP image carries `fetchpriority="high"` and must
never be lazy-loaded.

## Accessibility

The site passes **axe-core with zero WCAG 2.1 A/AA violations on all 111 pages**. Things that are
easy to break:

- **Colour.** `--accent-strong` (`#ff4d6d`) is a *fill* colour only — it fails contrast as text on
  light backgrounds. Use `--accent-text` (`#a4133c`) for text and `--accent-btn` (`#e0284a`) for
  button fills behind white text. On the dark `.guarantee` panel, use a light tint (`#ffccd5`).
- **Reveal animations.** `.reveal` starts at `opacity: 0` and JS adds `.revealed`. There is a
  `<noscript>` fallback and a `prefers-reduced-motion` block that force everything visible.
  **Do not remove them** — without them the page body is invisible when JS is blocked.
- **Forms.** Every input needs a `<label for="...">` matching its `id`.
- **Tap targets.** Nav, footer, breadcrumb and TOC links are held at `min-height: 44px`.

Re-run the audit any time:

```bash
npm install axe-core playwright
npx http-server . -p 8884 &
node axeall.js          # from the build tooling, see below
```

## Build tooling

The generator scripts are **not** in the publish directory — they were used to produce the HTML,
which is committed directly. Content lives in JSON, pages are rendered from a shared shell:

| Script | Purpose |
|---|---|
| `build_all.py` | Master build: seeds pages, ports shared sections |
| `build_blog.py` | Renders the 60 guide articles from `expansion.json` |
| `build_local.py` | Renders the 31 local landing pages from `kw/content.json` |
| `build_hub.py` | Service-areas hub, nav wiring, `sitemap.xml`, `_redirects` |
| `build_relink.py` | Internal link rewriting and the guides index |
| `a11y_fix.py` | Accessibility pass applied across every page |

Because output HTML is committed, **you can edit pages directly** without running anything. If you
regenerate, the scripts overwrite — check `git diff` before committing.

## Gotchas

1. **Netlify caches the bare `/` path.** After deploying homepage changes, verify with a
   cache-busting query (`/?cb=1`) if `/` looks stale to an external fetcher.
2. **Pretty URLs strip `.html` in served HTML** — so a link written as `/foo.html` renders as
   `/foo`. Both work; the canonical tag decides which Google indexes.
3. **Old guide filenames are still in the repo.** They are covered by forced redirects. Leave them.
4. **`.eyebrow` on dark sections** needs an inline light colour; the default token is dark.
